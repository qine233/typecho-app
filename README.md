# NLecho

一个给 [Typecho](https://typecho.org/) 博客用的原生 Android 客户端：**Kotlin + Jetpack Compose + Material 3**，数据全部走 Typecho 自带的 XML-RPC 接口，不依赖任何服务端插件就能看文章、写文章、管评论。

界面没有用 Material 默认那套（药丸高亮、tone 容器、TopAppBar），而是**深度仿小红书**：双列瀑布流、单列大图日记、笔记式详情页、自绘底部导航 + 居中的「+ 发布」方块。

它是我给自己博客（团子笔记）写的日常用 App，所以「一个博主 + 一台手机」这条路径上的细节做得比较满：离线补交、文章缓存、图片压缩上传、字体缩放全局生效。

想直接装：[Releases](https://github.com/qine233/typecho-app/releases/latest) 里有 CI 打好的 debug 包（Android 8.0+ 可装）。

| 首页：双列瀑布流 + 分类筛选条 | 日记动态：按日期分组的单列大图 | 详情页：笔记式正文 + 固定互动栏 |

## 能做什么

**阅读**
- 首页双列瀑布流，顶部搜索药丸 + 分类横向筛选条；翻页走站点真实分页参数，配骨架屏与进场动画
- 全站搜索：点搜索药丸进独立搜索页，关键词交给站点的全文搜索（走搜索结果的 RSS，见「全站搜索」），再并上本机已加载的笔记；命中处标黄，带最近搜索历史，离线也能翻出看过的东西
- 「日记动态」标签：把归在日记分类下的文章按日期倒序排成时间线，单列大图
- 详情页：多图 `HorizontalPager` 轮播 + 全屏查看器、正文图片懒加载、评论按 `parentId` 还原成嵌套回复树
- 进详情是「封面飞过去」而不是换页：卡片封面（含日记大图、搜索结果里那格缩略图）和详情页首屏大图是同一个共享元素，按文章编号认领，360ms 一起长大挪位；详情页本身只淡入淡出，页面再横着滑会让同一块图分成两股劲儿
- 长按卡片就地弹一张预览（248×320，走 `Popup` 所以不吃列表布局）：标题 + 摘要 + 分类 + 评论数，点它等于打开原文，点外面或返回键收起。预览尽量压在卡片正中，但会被夹在可视区里；没有配图时铺一块和列表文字封面同源的颜色，不留一格灰
- 底部固定互动栏：赞 / 收藏 / 评论入口，点赞收藏状态写本机，下次进来还在

**写作与管理**（登录账号是管理员时才会出现「管理」标签）
- 编辑器：Markdown 正文 + 实时预览、撤销/重做、全屏沉浸写作、分类与标签、存草稿
- 预览三种排布：只写 / 上下分屏（上写下看，边打字下面跟着长出来）/ 只看渲染结果。分屏是顶栏那颗眼睛一键开关，「只看预览」在「更多」里；顶栏再塞两个模式按钮标题就要被挤成竖排了，所以只留一个开关
- 预览停手 220ms 才渲，且渲在后台线程，长文不该卡住输入框；切走再切回来不会先空一帧
- 插图排序：正文里有 `![..](..)` 时编辑器下方排出一排缩略图（带序号角标），长按拖到想要的位置就当场改写正文那一段 Markdown —— 只搬那张图自己那一行，不会在原地留下空行，也不会把两张图粘成一行；这一步算进撤销历史，拖错了按一次撤销就回去
- 发布时间：高级选项里能挑日期和时间（新建默认此刻、编辑默认沿用原文时间），保存时原样送回站点，改老文章不会再被顺手顶到最新
- 发布之后会把站点回传的编号认回本篇，接着改就是原地编辑，不会再插第二篇（本站小回复会被 PHP 警告吃掉，认不回来时会明确提示，详见「PHP 8.4 的 warning 会吃掉小回复」）
- 编辑器本地自动存稿：输入停顿即落盘，进程被杀或闪退后重进会问一句要不要恢复
- 插图：从相册选图 → 本地压缩 → 上传 → 正文内联；配了 Cloudreve 就走 Cloudreve 拿永久直链，没配则走 `metaWeblog.newMediaObject`
- 管理台：文章列表（发布/草稿/私密状态切换、删除）、评论审核（通过 / 垃圾 / 删除 / 回复）、页面列表
- **重复文章清理**（管理 →「重复文章」）：一页一页把整站文章翻完（最多 600 篇），标题+正文归一后完全相同的算一组，**每组留最早的那篇**（编号小的兜底），多出来的默认勾上，一次删；同名但正文不同的另开一栏只给看不给勾，「日记」「未命名文档」这类占位标题不算同名。这个入口存在的原因就是上面那条 cid 被吞的坑——当年点两次发布留下的副本，靠手动翻列表是清不完的
- 详情读的是文章缓存（本站 `getPost` 会 500，命中缓存就再不回源），所以缓存必须跟着写操作走：编辑器存完把新内容合回缓存（只覆盖编辑器认识的字段，`link` / 作者 / 评论数这些还是留接口给的那份），删文章（单删、批量删）同时把内存和 `posts_cache.json` 里那篇摘掉，不然退回去看的还是改之前那版
- 网盘：配了 Cloudreve 就能在「管理 → 网盘」里浏览目录、看已用容量、传本地文件、下载回本机、建文件夹、重命名、移动、丢回收站，并给任意文件手动生成永久直链或一条带提取码的分享（详见「网盘管理」）
- 存稿/发布/删除之后，首页、日记、管理列表当场跟着重取，不用退出 App 重进

**健康记录**（可选，需要站点装 NoLineApi 插件，见下）
- 体重 / 体脂率按天记录，概览页给出当前值、BMI、目标进度、7/30/90 天变化与趋势折线图
- 断网时先进本机队列，恢复后自动补交；接口按天整体覆盖，重放安全
- **桌面小组件**（和买菜卡同一组规格，共用同一个 `WidgetSpec`）：2×2 是当前体重、涨跌、目标进度和一颗「记体重」；3×2 多出「10/16 称的」和进度百分比；3×3 再往下排「变化」三行（7 / 30 / 90 天各减了多少，基线取的是接口那三个区间，没有就标「无基线」）。BMI 那行只在三格高（`WidgetSpec.tall`）才画——两格高硬加一行小字，被压扁的还是按钮
- 体重卡的数字允许本机顶上：队列里那条日期不比缓存旧时，卡片显示的是它，并写明「还没传上站点」；但**涨跌、BMI、目标进度一律不凭空算**——那三样是服务端算出来的，离线时宁可空着。进度条同理，队列那条还没进 series，画不出真进度就不画
- 点「记体重」走 `nline://health/add`，进的就是健康页且**录入面板已经弹开**（体重预填上一次的值）；点「变化」那三行进健康页看趋势图。标题行那颗「刷新」只拉数据，不会替用户把队列里的记录提交上去
- 两家卡片吃的是同一份本机缓存，所以每次刷新都把**同一家三种规格**一起重画（只重画当前那张，另一张会停在旧数字上看着像算错了）。在 App 里称完重、记完账，对应那家当场跟上；开一次 App 则两家六种规格一起重画（`onResume`，升级之后系统不主动通知，不然会一直停在加载圈）

**买菜记账**（可选，同一个插件、同一个开关，入口在「健康」页顶部）
- 概览一屏读完：本月大额 + 涨跌、本周/本年/累计、近 7 个月柱状（空月也补零画出来）、本月分类占比、最近 12 天流水
- 「再加一样」一次买多样，合并成**一个**批量 POST；点分类 chip 就地按类筛本月流水，点任一行可改可删
- 涨跌是客户端算的（接口不做差），上周为空时画「—」而不是「省了本期全部」；本周/本月都带「3/7 天」这种已过天数标注，不会把没过完的区间当整段比
- 页面细节：金额一律等宽数字（`fontFeatureSettings = "tnum"`），连着记几笔那一列不会左右抖；预算条、分类占比条都是记完一笔从零涨过去（`animateFloatAsState` + `FastOutSlowInEasing`）而不是跳到位，涨的过程正好让人确认「就是刚才那笔」；「展开全部流水」补了淡色底，看着才像颗按钮
- 离线记账走本机队列：新增合并成一个批量 POST、拿到服务器返回的编号才算提交成功（没有编号的行改不了也删不了），修改走幂等 PUT，删除撞上「本来就没这条」当成功放过
- **月度报告**（点「近 7 个月」的月份，或右上角「本月报告」）：整月流水一次取回后由 App 自己算合计、开火天数、日均、单笔均值、最贵一笔、按日柱状、分类占比、最贵的几笔；‹ › 逐月翻，往后的月份翻不过去。站点只给「本月」和「近 7 个月」两样，任意月份的聚合只能客户端做（`limit=0` 才是不限条数，缺省只回最近若干条）
- 报告里会把**还没传上站点的本机记录**一起算进去，并在页脚写明「其中 N 笔还没传上站点」，不会因为离线而少算
- **预算**：总预算 + 八个分类额度，**周期能选「每周 / 每月 / 每年」**（默认每月；站点只把这三档自然周期预先聚合好了，自定义起始日得把全量流水拉到本机算，不值当）。超支时进度条画满并标「超了 ¥x」，同时常驻通知多一句「本周买菜超预算 x 元，蔬菜超了 y 元」，那句话里的「本周」跟着设置改口。预算**只存在这台手机**（`bills_budget.json`），站点没有这个接口，也不进离线队列——换设备要重设
- 进度条上那道**竖线标的是「这一期过了多少」**（周 2/7、月 20/31）：钱落在线左边就是比时间慢着花，光看「用掉 60%」说明不了任何事。区间一律由客户端按当天算（周从周一起），缓存里那个聚合的起点跟算出来的对不上就说明它是上个周期抓的，退回按天累加并在脚注写明「多半偏少」，不端着报一个错的数
- 分类额度只有「每月」这一档能算进度（接口只回 `kinds_month`），设成周/年时那些数存着不画、面板里当场提醒一句，切回每月就回来；「本月报告」页的预算卡同样只在每月档出现，按周/年设的预算跟整月报告不是一回事
- **桌面小组件**（长按桌面 → 微件 → NLecho，**三格规格随便挑**）：2×2 只留本月合计、今天花销和一颗按钮；3×2 多出「4 笔 · 19/31 天」和预算进度条加百分比；3×3 再往下排三行最近买过的流水。规格写在一个枚举里（`WidgetSpec`：排几行、字号、按钮多高），字号和留白跟着格子走，不是把同一张卡硬塞进小格子
- 卡片是**磨砂玻璃 + 大圆角**：`cornerRadius` 要 API 31，minSdk 26 用不了，所以根背景是 App 自己画的一张位图（能拿到壁纸像素就按卡片宽高居中裁一块、三次盒式糊掉；拿不到就退一步用 `getWallpaperColors` 那三个取色点画色场，再走同一条模糊），糊完再叠上原来那三层——上亮下暗的半透明色调、顶部一道薄光、1dp 描边——最后用 `DST_IN` 抠出 22dp 圆角，圆角外面真透明。深浅两套颜色走 `values/` 与 `values-night/`。为什么非要自己画：Glance 1.1.1 既没有 `blur` 也没有 `alpha` 修饰符（拆 AAR 确认过），`RemoteViews` 在 `android.jar` 里一个 blur 方法都没有，桌面进程肯不肯给卡片后面糊一层不由 App 说了算，所以「高斯模糊」只能是把糊好的图当背景递进去。代价：这块玻璃是壁纸的快照，壁纸换了按 `wallpaperId` 重画，卡片挪了格子不跟（小组件不知道自己摆在屏幕哪一格）；17 上实测第三方进程读壁纸像素要 `READ_EXTERNAL_STORAGE`（`getDrawable` / `peekDrawable` 都被拦），所以那条路是「能走就走」，色场那条才是保底
- 预算进度是**真的进度条**（`LinearProgressIndicator`，超支整条转提醒色并把「超了 x」加粗），不再是十个方块拼的字符条；流水那几行点一下直接进录入面板，**品名和分类已经替用户填好了**（走 `nline://bills/add?title=…&kind=…` 深链，中文按 UTF-8 百分号编码，`盐&糖` 这种带符号的品名也传得过去），还没传上站点的那几笔排在最前、金额标成提醒色，最底下是一颗通宽的「记一笔」
- Glance 的 `weight` 只有 `ColumnScope.defaultWeight()` 这一根没有系数的弹簧（等价于 `Dimension.Expand`），拿它吃掉「桌面给的高度」和「排版要吃的高度」之间的那点空隙，把流水和按钮粘成底部那一组；右对齐同样只能靠「`fillMaxWidth` + `TextAlign.End`」，品名列是死宽且在算文案时就截到六个字（Glance 不会自己打点），外层 Column 只放六段——超过十段会被静默截断，那颗主按钮会直接消失
- 三格都 `resizeMode="none"`：自由拉伸能拉出比排版还矮的高度，那颗按钮会被裁掉一半。3×2 也不排流水——两格高（178dp）塞一行流水，被压扁的就是按钮
- **设了预算之后卡片矮不下不塌了**：排版吃的高度是问宿主要的（`GlanceAppWidgetManager.getAppWidgetSizes(id)`——同一格 3×3 在模拟器上是 311dp，换台机器能矮 60dp），不够高就从最不要紧的地方开始让位：少摆一行流水 → 撤掉进度条（「还剩 800.00」那行小字留着）→ 最后才不写「今天」，那颗**定高**的「记一笔」谁都不能压。问不到高度就退回按规格排；整张降级表是纯函数 `billsFitPlan`，单测拿假高度逐档核过。卡片留白同时收成一组常量（上下 10dp、流水行距 4dp），模拟器实测弹簧空隙从 8dp 回到 42dp
- 卡片只读本机缓存，断网也画得出来；标题行右侧那颗「刷新」只拉数据、**不会**替用户把队列里的流水提交上去。三种规格吃同一份缓存，所以任何一次刷新都把桌面上所有卡片一起重画（只重画当前那张，另一张会停在旧数字上看着像算错了）。在 App 里记完一笔、改完预算，卡片当场跟上；开一次 App 也会重画一次（升级之后系统不主动通知，不然会一直停在加载圈）

**通用**
- **底部导航是一颗悬浮的液态玻璃胶囊**：离底边抬起一截，四周不贴边，底下压着页面内容。玻璃是真的透——整块页面先被录成一层可采样画面（Haze），胶囊拿它做背景模糊，所以卡片滚过去时能看见颜色在玻璃下面化开；上缘再叠一道由卡片色淡出的反光，配 1px 描边和一层投影撑出厚度。Android 12 以下拿不到 `RenderEffect`，自动退成底色更实的毛玻璃，形态不变。代价是这一圈不再由外层 Scaffold 占位：每个 Tab 页（含最右那格「宝塔」）各自用 `rememberTabBarInset()` 把列表底部和 FAB 让开，详情页那类不带底栏的页面不受影响
- **五个 Tab 页的顶栏是一条通栏磨砂玻璃**：贴住屏幕顶部、左右不留缝，也不做成悬浮胶囊——一旦留缝，列表滚上去的内容就会从缝里钻出来顶在状态栏时间旁边。材质和底栏同源（`Modifier.noLineGlass`：Haze 录页面 + 46dp 模糊 + 上缘反光），但 tint 压到 74% 并加了点噪点，是磨砂不是透明玻璃（底栏那颗胶囊仍留着 42%，要看得穿）；四条描边只有下缘那条露出来，正好当发丝分隔线。每页自己 `hazeSource` 一份画面给玻璃采样（`hazeSource` 必须是 `hazeEffect` 的兄弟节点，写成父子就等于让玻璃去模糊自己），让位高度由 `onSizeChanged` 实测回传，不写死：首页有分类条和没有分类条差一行。管理页的快捷入口行也一并挪进列表当第一个 item，否则它永远停在玻璃外面
- 深色模式（跟随系统 / 浅色 / 深色）、字体缩放（全局生效，包括正文渲染区）
- 文章列表持久化缓存，冷启动先出内容再刷新
- 设置 → 检测更新：问 GitHub Releases 要最新版，有更新就下 apk 交给系统安装器；下载可选 GitHub 镜像站加速，下完对 sha256
- 设置 → 关于：**开源地址**那张卡写着完整的 `github.com/qine233/typecho-app`，点开进浏览器，右边的「复制」只把链接丢进剪贴板（有人是想在电脑上打开）。地址由 `ReleaseRepoOwner` / `ReleaseRepoName` 拼出来，跟「检测更新」查的是同一个仓库，改了仓库名不会两边对不上
- 设置 → 数据与存储：按「安装包 / 图片缓存 / 更新包 / 文章缓存 / 其他缓存 / 本地草稿 / 待同步记录 / 账号数据」分类列出实际占用并画成占比条，缓存可单类清理或一键全清；草稿和待同步队列只报数、给逐条删除和立即补交，永远不进「清理缓存」，不会被顺手清掉
- 设置 → 后台与通知：常驻一条工作状态通知，写清还有多少条记录没交到站点、上一次补交是什么时候、这个月哪几类买菜超了预算，按「待同步 > 预算超支 > 本地草稿」挑一条当标题，点开直达对应那页（待同步和草稿进「数据与存储」，只有超支时进「买菜记账」），通知上带「立即补交」；后台补交走 WorkManager 周期任务（最短 15 分钟一轮，由系统 JobScheduler 排，进程被杀排期还在），也可以整个关掉
- 退出登录会清掉本机保存的凭证
- 底栏最右那格「宝塔」（管理员才有；设置 → 服务器运维 →「宝塔面板」是同一个入口）：读那台机器的 CPU / 内存 / 负载 / 运行时长 / 磁盘 / 网速，翻数据库、计划任务、面板日志，外加几个低风险动作；「网站管理」「数据库管理」「FTP 管理」「MySQL 管理」「计划任务」各自是专门的一页，进去像面板那样按对象操作，不用调用台（详见「服务器运维：可选接宝塔面板」）

## 自动构建与下载

`.github/workflows/build-apk.yml` 在 GitHub 上跑编译，不用本地装 Android Studio：

| 触发 | 结果 |
| --- | --- |
| 推 `v*` 标签（如 `v1.0.0`） | 建 Release，把 APK 作为附件挂上去，可直接下载装机 |
| push 到 `main` / PR / 手动 Run workflow | 只跑测试 + 编译，APK 放在那次运行的 **Artifacts** 里 |

所以想要一个能装的新包：合并到 `main` 后去 Actions 页面拿 Artifacts；想给外人一个稳定入口，就打 tag。

应用内「检测更新」按 tag 的数字段比版本（`v1.0.1` 与 `1.0.1` 等价），并且**只认同渠道的附件**：debug 包名里带 `debug`，正式包不带。渠道不对时提示「没有本机这个渠道的包」而不是硬下——包名和签名都对不上，下回来也装不进正在跑的这份。

### 下载走 GitHub 镜像

直连 `objects.githubusercontent.com` 拉 19 MB 的包，在这台机器上 240 秒只挪了 6.5 MB（约 27 KB/s），而 `api.github.com` 一次几百字节的请求 0.7 秒就回。所以**查版本仍走官方接口，只有下载 apk 这一步需要镜像**：设置 → 检测更新 → 「更新来源」里选一家，选中的排最前，失败或校验对不上会自动换下一家。

`GithubMirror` 里现在有四家，2026-10-15 用 `v1.0.8` 的包逐个实测过（取首块认 `PK\x03\x04`，再整包下完对 sha256）：

| 来源 | 下载附件 | 转发 `api.github.com` | 整包耗时 |
| --- | --- | --- | --- |
| GitHub 直连 | 慢 | 0.7s | 240s 没下完 |
| `gh-proxy.com` | 通 | 通 | 3.5s |
| `ghfast.top` | 通 | 403，只转文件 | 12s |
| `ghproxy.net` | 通但很慢 | 403，只转文件 | 240s 没下完 |

地址是前缀拼接：`https://gh-proxy.com/` + 原始 `https://github.com/...` 或 `https://api.github.com/...`。另外探过但没收的：`github.moeyy.xyz`、`gh.llkk.cc`、`mirror.ghproxy.com`、`ghp.ci`、`hub.gitmirror.com` 连不上，`gh.con.sh`、`gitproxy.click`、`ghproxy.cn`、`dlink.host` 回的是 HTML 页面。镜像站是会换的，所以来源列表要定期重测，代码里那两条兜底链（`apiChain()` / `downloadChain()`）就是为一家死了准备的。

**镜像下来的包一定要对校验和**：GitHub 接口的附件里带 `digest`（形如 `sha256:dc9b…`），`UpdateRepository.download` 下完会重算并比对，另外还看首 4 字节是不是 zip 的 `PK\x03\x04`、大小跟接口报的一不一致，任一项不对就换下一个来源。实测 `gh-proxy.com` 与 `ghfast.top` 下到的包 sha256 与接口 `digest` 完全一致。要点是：**校验和来自接口那一次请求**，所以接口只走 `apiChain()`（直连优先，挂了才轮到能转发接口的 `gh-proxy.com`），不受这里选的下载来源影响。直连拿到接口时，sha256 是 GitHub 说的，镜像换包必然对不上；只剩接口也走镜像这种极端情况，这份校验和就只拦得住截断和 HTML 错误页，拦不住主动作恶——真要把这条链彻底锁死，得给发布物做签名清单（`minisign` 之类）再随仓库分发公钥。

签名这块有个坑值得记一下：Actions 每台 runner 都是新的，`~/.android/debug.keystore` 当场现生成，所以早期每个 Release 的 APK 签名都不一样，App 内下载完交给安装器只会得到 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。现在 `keystore/debug.keystore` 提交在仓库里，本机与 CI 都用它签（口令就是 Android 通用的 `android`/`androiddebugkey`），发布出去的包才互相覆盖得了。**装了 `v1.0.1` 及更早的包要先卸载一次**，那两版是临时密钥签的，跟这份对不上。要出正式签名的 release 包，需要自己补两步：

1. 仓库 Settings → Secrets and variables → Actions 里加 `KEYSTORE_BASE64`（`base64 -w0 your.jks` 的结果）、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`
2. `app/build.gradle.kts` 的 `release` 里加 `signingConfig`，从上面几个 secret 读，再在工作流里加一步 `assembleRelease` 并把产物一起上传

仓库里那份只是 debug 密钥，作用就是让同一渠道的包能互相覆盖升级；正式签名的私钥仍然不要提交，一旦进过仓库历史就收不回来。

### 下载挂在前台服务上，切后台不断

二十来 MB 的包按上面的速度要下十几分钟，所以这一步不能放在 ViewModel 的协程里——设置页一退、进程一被回收，下载就断了。现在它由 `UpdateDownloadService`（`foregroundServiceType="dataSync"`）扛：点「下载并安装」→ 服务先同步把前台通知挂上（系统只给这几秒），再开协程下载。

- **进度那条通知**（id 4202）是服务的凭据，写的是 `14.6 MB / 21.3 MB · 68%`，字节数排在百分比前面（慢的时候人想知道的是还剩多少）；`setSilent` + `setOngoing`，只在下完那一刻响。整数百分比变了才重发一次，不然每 64 KB 一回调用会被系统限流。来源没报 `Content-Length` 时画不确定进度条，不硬编一个假百分比。
- **结果那条换个 id**（4203），所以服务 `stopSelf` 之后它还留着，人不在 App 里也有入口。它的点击意图是回 App 的设置页（`nline://update`），**不是**直接起安装器：那个意图是隐式的，而且后台起 Activity 从 Android 10 起就被系统拦，静默失败比不响更糟。回到前台后再走 App 里那条已经跑通的安装路径。
- 服务写、设置页读的是一块共享状态（`AppContainer.updateDownload`，一个 `StateFlow<UpdatePhase?>`），不是事件总线，所以切走再回来页面能立刻接上当前的进度；ViewModel 重建时如果下载已完成，页面显示「立即安装」而不是又下一条。
- 下载完自动拉起安装器只发生在**这一页亲手按下、且那一刻人还在页面上**的时候；否则留通知和按钮，别抢焦点。
- 缓存文件按版本命名（`update-1.14.1.apk`），所以旧版残留不会被当成这次的新版交给安装器。
- 「取消」走 `ACTION_CANCEL`：那是用户亲手取消，不写成失败，通知和状态一起清掉。

为什么不用 WorkManager 的加急任务（`setExpedited`）：那条路有约十分钟的硬额度，超了就被系统掐掉，对 27 KB/s 的直连来说根本下不完；而它内部本来也是借一个前台服务，省不下通知。

## 登录：直连站点自带的 XML-RPC

App 只认站点自己的 XML-RPC 端点，不需要额外配置。

1. 登录页填三项：
   - **站点地址**：`https://your-blog.com`（必须 HTTPS —— `network_security_config` 关掉了明文流量，http 站点会被系统直接掐断）
   - **XML-RPC 路径**：默认 `/action/xmlrpc`，改过伪静态的按实际填
   - **用户名 / 密码**：Typecho 账号
2. 「记住登录状态」勾上才会把密码留在本机（DataStore 明文，见「已知限制」）

XML-RPC 是 Typecho 核心自带的（`var/Widget/XmlRpc.php`，路由 `do(action='xmlrpc')`），后台没有开关，装了站点就能直连。

登录时先调 `blogger.getUsersBlogs` 验证，并从返回里读 `isAdmin`，决定要不要给你看「管理」和「健康」标签。

用到的接口方法：`blogger.getUsersBlogs` / `blogger.deletePost`、`metaWeblog.getRecentPosts` / `getPost` / `newPost` / `editPost` / `getCategories` / `newMediaObject`、`wp.getComments` / `newComment` / `editComment` / `deleteComment` / `getPages`。

> Typecho 的 XML-RPC 和 WordPress 有几处不一致（参数顺序、`post_status` 命名、PHP 8 的 warning 会混进响应头），`XmlRpcClient` 里都按 Typecho 的实际行为处理了。

### PHP 8.4 的 warning 会吃掉小回复

站上跑 PHP 8.4 时，XML-RPC 的响应体前面会多出一段固定的 228 字节 deprecation 提示（`xml_set_object()` 那条），但 `Content-Length` 头是按不含警告的纯 XML 长度算的。客户端按这个长度读，读到的 XML 就比实际少 228 字节：

- 回复体超过 228 字节的没事，只是尾巴被截掉一截，`XmlRpcClient` 会先把警告前缀剥掉再解析
- **XML 本身不足 228 字节的，一个字节都读不到** —— `metaWeblog.newPost` 只回一个数字 cid（约 140 字节）、`metaWeblog.editPost` 只回 `<boolean>1</boolean>`，正好都在这一档里

所以发布成功但客户端拿不到新编号，看起来就像「同一篇发两次、多出一篇重复的」。App 侧的处理是：先认站点回传的 cid，拿不到就立刻用 `metaWeblog.getRecentPosts` 取最新一篇，标题能对上就把它当成本篇的编号（页面走 `wp.getPages`）；连这一步也认不回来时，Toast 会明说「站点没有回传编号」，提醒从列表里继续编辑而不是再点一次发布。

**站点侧改了更彻底**：在宝塔的 PHP 8.4 配置里把 `display_errors` 设为 `Off`（或从 `error_reporting` 里去掉 `E_DEPRECATED`），warning 就不再进响应体，小回复立刻恢复正常长度。改完 `metaWeblog.newPost` / `editPost` 的返回值才真正读得到，不用依赖上面这层兜底。

## 全站搜索：只能走站点的搜索 RSS

首页顶部的药丸点开会进独立的搜索页（不再是在首页就地过滤），进去自动弹键盘。输入停顿 350ms 才发请求，按下键盘上的「搜索」则当场发。

Typecho **没有**给搜索留任何 XML-RPC 口子：`wp.getPosts` 根本没实现（`var/Widget/XmlRpc.php` 的方法表里就没有它），也没有 `mt.search`。能查全站正文的公开出口只有一个 —— 站点自己的搜索结果订阅：

```
GET https://<site>/feed/search/<关键词>/
```

它会 301 到 `/index.php/feed/search/<关键词>/` 再回 200（`application/rss+xml`），所以 `SearchFeedApi` 先按重写后的地址试，不是订阅格式再退到 `index.php` 那条。实测下来的规矩都写进了代码和单测：

- **一次最多 10 条，没有翻页参数**。所以搜索结果分两段：站点全文（≤10 篇）+ 本机已加载的笔记（拿首页/日记落盘的 `posts_cache.json`，最多 120 篇，按 cid 去重后只补站点没给的那些）。列表底部会写明「站点一次最多回 10 篇」而不是假装这就是全部。
- **关键词里带 `/` `:` `,` `?` 会被路由吃掉**（`/feed/search/a%2Fb/` 直接 404），这种词根本不发请求，当场告诉你「站点的搜索接口不认」。空格要编成 `%20` 而不是 `+` —— `+` 会被截断成前半截词。
- **零命中是 200 + 一个空 `<channel>`**，不能当失败；反过来回了 200 却不是订阅格式，才算「站点没有这个接口」。
- item 的 `<title>` 常常是空的（日记类文章没标题），`<description>` 是被截断过的摘要，`content:encoded` 才是编译好的**完整正文**。所以搜出来的每一条都会塞进 `PostCache` —— 本站 `metaWeblog.getPost` 在 PHP 8.4 下必 500，不塞进去点开就是一句加载失败。
- 时间是 RFC 822 的 `pubDate`（`+0800`），而 `Post.dateCreated` 用 epoch 秒，两套解析不能混。
- 响应被截断时（PHP warning 前缀那类老问题）宁可丢掉最后一条不完整的 item：`link` 里的 cid 正好被切掉一位，就会认成另一篇文章。

高亮分两处：详情页那段是站点自己标的 —— `content:encoded` 里命中处会带 `<mark>`，正文渲染器照原样画出来；列表行里那几处黄标是客户端做的（`SearchHighlight`），把查询按空白切成词，在标题和摘要上做大小写不敏感的命中段标色。

搜索历史存最近 10 条，只在**按下搜索**或**点开某条结果**时记录 —— 攒词自动搜出来的那些半截词不进历史。可以单条删（点词）也可以整列清空。

## 健康记录与买菜记账：需要 NoLineApi 插件

这两个功能是可选的，不装插件其余功能照常。「健康」标签只对管理员账号显示，读者账号看不到；记账入口在「健康」页顶部的「买菜记账」胶囊里，不占底部第六个标签。没配好接口时点进去是一页配置引导，不会白屏。前提是站点装了配套的 `NolineApi` Typecho 插件（REST 端点：`ping`、`theme`、`health`、`health/records`、`bills`、`bills/records`）。

配置四步：

1. 后台装好并启用 NolineApi 插件
2. App 设置 →「健康记录接口」→ 填接口密钥（和插件里配的那把一致）
3. 只想在 App 里看不记的话，后台别开「允许写入」；要记就打开
4. 点「保存并自检」

自检会真的跑一遍读写：先按 `/api/…` → `/index.php/api/…` → `/?noline_api=…` 三种 URL 形态探测出可用的一种并记住，再发一次读取和一次「必定无效」的写入探针（weight 0，服务端会直接拒掉，不落库），从而区分「密钥错」「站点关了」「只读」「路径不通」。结果卡片会用不同文案告诉你卡在哪一步，包括把服务器原话和解析报错分开显示。

写记录前 App 本地先校验：日期必须是不晚于今天的 `yyyy-MM-dd`（严格解析，`2026-02-30` 这种会被拒）、体重在 20–400 kg、体脂率异常只提示不拦。

记账这边和体重有几处规矩不一样，都是对着插件源码（`plugins/NolineApi/Bills.php`）核过的：

- POST **永远新增**，没有「同日覆盖」，所以离线重放必须先攒着、合并成一次批量提交，不能像体重那样随手重发。
- 批量提交的响应里 `ids[]` 是按「通过校验的那几条」同序给的，App 必须把它认回本地条目 —— 没有服务器编号的行既改不了也删不了；`invalid[]` 装的是**品名**（截到 20 字），不是体重那边的日期。
- PUT 要在 body 里带 `id`（缺了 400、查无此条 404），改了日期 `id` 也不变，所以日期不能从 `id` 反推；`time` 一直是当初录入那一刻，`updated` 为 0 表示从没改过。
- DELETE 的 `id` 在 **query** 里；查无此条回 404，客户端按删除成功放过（重放第二次就是这个）。
- 分类代码是稳定的 8 项（`veg/fruit/meat/fish/egg/grain/seasoning/other`），写错的代码服务器**静默**归到 `other`，所以选择器只给这 8 个，标签由 App 自己出。
- `GET /api/bills/records` 的 `limit` 默认 50，取的是区间**尾部** 50 条，而响应里的 `amount` 只算真返回的那些 —— 要整月合计必须显式传 `limit=0`。
- 一条流水都没有时，六个区间（`totals`/`week`/`prev_week`/`month`/`prev_month`/`year`）和 `max` 都是显式 `null`，不是「金额为 0」。
- 概览只给「本月」和「近 7 个月」两档聚合（`months` 固定 7 项、`kinds_month` 只有当月），**任意月份的分类占比和按日明细服务器不给** —— 月度报告是客户端拉整月流水自己算的，本机队列里还没传上站点的几笔也得并进当月，否则离线记账那几天会是空的。
- 预算没有对应接口，是本机的一个数（`bills_budget.json`），不进离线队列；算超支时同样要带上没传上去的那几笔。月报按月份缓存最近 12 个月（`bills_reports.json`），重新取数失败时：有旧的一份就先给旧的并在页顶标明这是存着的，没有就走「取不到」那一页。

## 插图图床：可选接 Cloudreve v4

不配也能用，插图照旧走博客自己的 XML-RPC 附件上传。配了之后编辑器只认 Cloudreve —— 悄悄退回旧通道只会让人以为图床没坏，所以当场报错更实在。

配置：设置 →「图片上传图床」→ 填 Cloudreve 地址 + 登录邮箱 + 密码 → 点「保存并自检」。自检只试一次登录，不往云端写任何东西；密码和 NoLine 密钥一样经 Keystore 加密后存本机。图片落在 `/blog/<年>/<月>/<毫秒时间戳>.jpg`（目录名在 `CloudreveRepository.ImageDir`，暂时没有界面可改），路径上缺的年月目录由 Cloudreve 顺手建出来。

v4 有几个和直觉不符的地方，都是对着源码核过的：

- **没有「长期 API 密钥」**。`Authorization: Bearer Cr…` 那种是请求签名，进不去文件接口；能用的只有 `POST /api/v4/session/token` 换出来的 JWT，默认一小时过期。所以 App 存的是账号密码，令牌快到期或撞上鉴权类错误码就重登一次（只重登一次，不循环）。
- **直链只能用 `PUT /api/v4/file/source`**。它给的 `/f/<id>/<name>` 游客也能打开，服务端每次 302 到一个新鲜签名的地址，贴进文章不会失效。`POST /api/v4/file/url` 的签名地址默认一小时就过期，而且过期后照样回 HTTP 200 + `{"code":40005}` —— 用它贴图，文章里的图会在一小时后无声消失。
- **状态码没有信息量**。连「未登录」都是 HTTP 200，成败只看响应体的 `code`，所以只有返回的不是 JSON 时才拿状态码兜底。
- **`PUT /api/v4/file/content` 不是上传口**。它是在线编辑器改文件内容用的，拿它上传会撞上 `{"code":50004}`。真正的上传一定是三步：`PUT /api/v4/file/upload?uri=…` 建会话 → 按会话给的 `chunk_size` 分片送（本机/中转策略 `POST /file/upload/<session>/<index>`，裸字节且 `Content-Length` 必须正好等于这一片的长度；OneDrive 这类直传策略则带 `Content-Range` PUT 到会话给的预签名地址，传完再 `POST /callback/onedrive/<session>/<secret>` 通知主机收尾）→ 收尾由主机把占位文件转正。分片中途失败，App 会 `DELETE /file/upload` 把会话连同占位文件一起撤掉，不在网盘里留残骸。
- **`{"code":-1}` 是「服务端自己吞了原因」**。Cloudreve 把没包装成业务错误码的内部失败统一回成 `-1` + 空 `msg`，真实原因只在站点的日志里（`data/logs/cloudreve.log`，可按响应里的 `correlation_id` 对）。上传撞上它，基本是当前用户组的存储策略不能用：文件接口的 `policy_id` 只对「导入版本」生效，普通上传的策略由用户组决定，客户端挑不了。本站最后撞上的原因就是 OneDrive 存满（2026-10-13 确认）—— 建上传会话要在存储端开写入口，空间满了这一步直接失败，读文件却一切正常。
- **站点开了登录验证码、账号开了二步验证，App 就登不进来**。这两种情况会直接说清楚原因，不会闷着转圈。

### 网盘管理（管理 →「网盘」）

配了 Cloudreve 才会出现这个入口。进去能浏览目录、按名字排序、游标翻页（`pagination.next_token` 传回 `next_page_token`，翻到底时这个键根本不存在），建目录、重命名、移动、删除、上传、下载，以及给任意一个文件手动生成永久直链或一条分享 —— 点文件那行就弹直链，「复制链接」直接进剪贴板，贴文章和图床走的是同一条 `/f/…` 地址；改名/移动/删除/分享都收进每行末尾的「更多」菜单里。

- **上传走 SAF，选哪个文件传哪个**。顶栏「上传」按钮开系统文件选择器，拿到 `content://`  uri 后只开一条流按顺序读（内容提供器的流不一定支持 seek，而分片本来就是从头一片一片发的），照旧走「建会话 → 分片 → 回调收尾」那三步，页面顶部给一条「已送 / 共」的进度。同名文件会先在本页里避开重名（`名字(1).jpg`），空文件和读不到大小的文件直接拒掉。
- **下载交给系统 `DownloadManager`**。`POST /api/v4/file/url` 拿一次性的签名地址（默认一小时过期，只够立刻交给下载器），落到公共 `Download/`，进度在通知栏。目录不给下载 —— 这条路对目录会回 `40081`（聚合的 `40077 Entity not exist`），所以下载按钮只出现在文件行上。同样是 `40077/40081`，当年上传没成功留下的「空壳记录」也会这么报，所以这两个码单独翻成「网盘里留着这条记录，但存储端已经没有这个文件了」，而不是把 OneDrive 的英文原文甩给人看。
- **分享管理是独立一页**（网盘顶栏「分享管理」）。`GET /api/v4/share` 列自己建过的分享（`page_size` 下限是 10，给 5 会被拒成 `40001 PageSize too short`），能复制链接、能撤销；`DELETE /api/v4/share/:id` 只让链接失效，文件不动，撤销要二次确认。分享 id 是链接里 `/s/` 后面那一段，把带提取码的整条路径塞进去会被判成非法 ID。
- **建分享只填提取码和有效期**。`PUT /api/v4/share` 的 `data` 直接就是拼好的完整链接，私密分享会把提取码当路径段缀在末尾（`/s/<id>/<提取码>`），复制出去对方不用手输。提取码按服务端的规矩先挡一道：只收字母数字、最长 32 位；有效期给「不过期 / 1 / 7 / 30 天」四档（秒数，0 不过期）。
- **删除只丢回收站**。`DELETE /api/v4/file` 不带 `unlink/skip_soft_delete` 就是软删除，默认留 7 天，网站后台能捞回来；真·彻底删除要额外权限，普通账号会被 403「advance delete permission is required」拦下，所以 App 不开这个口子。
- **改名之后 path 会变**。网盘的 `path` 尾段就是文件名，重命名后旧 path 已不存在，界面会连 `path` 一起换掉，后续操作才不会打到已经没了的文件上。
- **不能把目录移进它自己或它的子孙里**，Cloudreve 对这种移动直接报错，挑目标目录时就先禁用掉。
- **顶部那行容量只是 Cloudreve 自己记的账**（`GET /api/v4/user/capacity`，4.14.1 上 `user`、`user/quota` 都是 404）。它给的是「已用 / 策略配额」，跟存储端的真实剩余是两回事 —— 本站实测这里显示 5 TB 只用了 1%，OneDrive 其实早写满了，所以它不能用来预警上传失败，只能当个用量概览看。取不到就整行不显示，不会占错误位。

## 服务器运维：可选接宝塔面板

不配也照样用。这一页上半是只读看板：CPU / 内存 / 负载 / 运行时长 / 磁盘 / 网速、数据库、计划任务、面板日志的列表、任务日志，外加重载或重启 nginx / mysql / php-fpm、把一条计划任务立刻跑一次、重载面板本身。入口有两条：底栏最右那格「宝塔」（只有管理员账号有这一格），或者设置 →「服务器运维」那张卡。

**网站管理是独立的一页**，不靠调用台。看板顶部「进入网站管理」进去之后是站点列表（域名几个、根目录、PHP 版本、备份份数、证书剩几天、到期日期，按域名或备注搜），点一个站点进它的九个页签，每一个都能真的动手：

- **域名**：列子目录绑定、DNS 是否解析、有没有进证书；加域名发得出，删域名面板那边没有可认的 action，所以界面上不给按钮
- **网站设置**：切 PHP 版本（含纯静态）、改运行目录、改默认文档顺序、看目录绑定和绑的 FTP 账号
- **伪静态**：列该站可用的模板名单；切换模板这个 action 面板收不到有效参数（试遍三种形状），这里只读
- **SSL**：贴现成证书 + 私钥部署、关闭 SSL、强制 HTTPS 开关；Let's Encrypt 签发走证书模块，不在这条接口上。`GetSSL` 回包含私钥原文，解析层一次都不读它，界面上也没有能把私钥显示出来的路径
- **重定向 / 反向代理**：301 / 302 按路径或域名跳转、`/api` 这类路径转发到后端端口，建、改、删都在页面上（删代理只有 `RemoveProxy` 这个名字面板认识）
- **日志**：访问日志和错误日志并排，各自截尾 400 行——实测错误日志单次 1.7MB，整段交给列表会把这页卡死；访问日志开没开是切 `logsOpen`（它是「翻转」不是「设为开」，状态要从目录级配置读回来）
- **安全**：限速三个值（并发 / 每 IP / KB/s）、目录密码保护（≤8 位）、域名级 301、响应头那五项开关
- **备份**：立刻备一次，产物落在 `/www/backup/site/<站点名>/`

写操作分两种闸门：停用 / 启用 / 切 PHP / 改运行目录这类点一下就成；删站、关 SSL、删重定向、删代理要点确认；**删站要手打站点主域名**才能按下去。重定向和代理的表单在本地先校验（名称、目标 URL 要带协议、来源路径以 `/` 开头），发出去之前不让下一步。

**数据库管理也是一页**，看板顶部「进入数据库管理」进去。列表一行一个库（引擎、账号@地址、占用、备份份数、建库时间），搜库名或备注是**在本机过滤**——`getData` 那个 `search.value` 实测面板根本不认。点一个库进它的三个页签：大小与表（面板记的表清单和原生 `SHOW TABLES` 各摆一份，数目对不上就说明有表不是面板建的）、授权（这台服务器上谁能碰哪些库，只留这个库和「全局权限」那几条）、备份（列产物和大小）。六只能动的手：建库（库名 / 账号 / 密码 / 访问地址 / 字符集，账号名跟着库名走，手改过一次就不再覆盖）、改密码、改访问地址、立刻备份、删库（要手打「删除」）、删账号。

**MySQL 管理**是它旁边那一格，对应面板「数据库 → MySQL 管理」那一整排：运行时计数、内存参数、服务器信息、安装状态四块只读，外加六只能动的手——改超时、清 Binlog、开关守护进程、加账户、删账户、读日志（日志正文几百 KB，只在点了「读日志」之后才发请求，收在弹层里）。

面板做不到的，界面上就没有那个按钮，并且会写清楚为什么没有：

- **改库的字符集**：`GetDbType` 那一口实测报错，库建出来就只能靠 SQL 自己 `ALTER`
- **还原 / 导入 SQL**：接口只认服务器磁盘上已有的 `.sql` 路径，手机上没有这条来路
- **删备份文件**：`DelBackup` 回「已删除」而文件纹丝不动，这种事不能给 App 一个按钮
- **改权限**：面板网页那一格改权限没有对应 action，页面上只能读
- `getData` 查 `databases` 每行都带 `password` 原文，解析层按键名直接丢，模型里没有一个装得下它的字段

**FTP 管理**同样是一页。列表一行一个账户（用户名、状态、根目录、已用 / 上限、建号与到期时间），手有五只：建号、暂停 / 启用、改密码（含批量）、限速与容量、删除（手打「删除」）——外加看登录日志和操作日志。两处照面板网页的脾气来：

- **根目录跟着账户名预填**成 `/www/wwwroot/<账户名>`。默认那格停在 `/www/wwwroot/` 这一层，手一抖不改就等于把整站根目录交给这个账户，所以这一条不是可选的贴心，是防误操作
- **限速三格（下载带宽 / 上传带宽 / 空间上限）是整体写进去的**：`ModifyFtpUserAccess` 一次吃三个值，面板没有「只改其中一格」的口，留空发过去就是 0、也就是不限——那等于悄悄抹掉人家原来的限额，所以三格都得填，一个都不给留空。这一格也**没有读回的口**，发出去只回一句「修改成功」，实际生效值只能去面板网页那一行看

做不到的三件：改备注和改根目录（接口侧六个候选 action 名实测全回「指定参数无效!」，面板网页点两下就能改的事这里就是做不到）、改 FTP 端口（`setPort` 改的是整台服务，一动手所有账户都得重连，没摆出来）、开关日志记录（那个 toggle 实测按不动，日志只做只读）。还有一条实测到的副作用：**删账户不会带走根目录**——账户没了，`/www/wwwroot/` 下那个目录原样留着，确认框里就把这句话写在那儿。

**计划任务**也是一页，和数据库、FTP 那两张排在同一排，点「进入计划任务」进去。列表一行一个任务（任务名、周期文案、启用 / 暂停、脚本或备份目标、归的分类），按任务名或脚本内容搜——这个口面板不给分页也不给搜索参数，整张表一次取回来在本机筛。手有八只：建任务、编辑、启用 / 暂停、立即执行、看详情（信息 + 执行日志两个页签）、清空日志、删任务、批量（启用 / 暂停 / 删除 / 立即执行 / 归到分类）。新建的表单是「八种周期 × 六种种类」的组合：按分钟、每 N 分钟、按小时、每 N 小时、每天、每周、每月、自定义 crontab 表达式，配 Shell / Python / Go 脚本、URL 取回、备份数据库、备份网站目录、备份指定目录，周期决定要填哪几格（只有按小时及以上的周期才有「时刻」两格），种类决定下面摆哪一格——脚本框、URL、还是「备份对象 + 留几份 + 备到哪」。删任务、批量删除、立即执行都要亲手打一遍关键词；批量启停只弹确认、不打字，确认框里把要动的是哪几条点名出来。

这一页的坑几乎全在「写」那一侧，实测之后都写进了 `BtCronApi` 的类注释：

- **时刻写进去叫 `hour` / `minute`，读出来叫 `where_hour` / `where_minute`**。建任务时发 `where_hour=5/where_minute=6`，那一格落回 `null`，列表里只剩干巴巴一句「每天」；改发 `hour=5/minute=6` 才存成 05:06。`modify_crond` 一样，而且两个名字一起发时是 `hour` 赢。所以改任务时两个键都盖成新值——那一行原本整行带回去，旧时刻就躺在里面
- **改任务是整行覆盖**：`modify_crond` 只认你发过去的那几格，没发的直接清空。界面因此从列表那一行取底稿，只盖用户在这张表单里摆出来的格子
- **面板那一行的 `name` 不会跟着改**，改标题要动的是 `rname`；`sBody` 才是脚本正文
- **`set_cron_status` 是「翻转」不是「设为开」**，所以确认框先说现在读到的是什么状态，按完再重读列表核对；`set_cron_status_all` 那条批量的逐条判决实测会撒谎（回「成功」而状态没动），批量一律以重读到的列表为准
- **「立即执行」走批量的 `exec`**，面板单独那个 `set_execute_script` 按下去没反应；实测暂停中的任务被 `exec` 一样会跑，所以那颗按钮的确认框把这句话写在上面
- 做不到的几件没摆按钮：日志的下载 / 导出、crontab 服务自身的健康检查与修复、把任务置顶、URL 任务的连通性探测，实测要么 no-op 要么根本没有 action 名；`set_auto_config`、`set_rotate_log_status` 这两个名字看着像设置、实际会**建出一条新任务**，更不可能给它们一颗开关。分类能建能归，面板没有删分类的口

- **按完一律重读**：这一页的写操作发完都再取一次列表，界面上的状态来自重读到的那一行，不是面板那句「修改成功」。

底栏最下面还挂着「全部接口 · 通用调用台」：[官方接口文档](https://docs.bt.cn/api/)里那 329 条接口（19 个模块、522 个参数）全部随包打进来，没有专门页面的接口在这里翻。它是兜底入口，不是网站管理的操作方式。

配置：面板「网站 → 接口 / API 通信」打开总开关 → 复制密钥 → App 里填地址 + 密钥 →（自签证书就打开「信任自签证书」）→ 点「保存并自检」。

- **地址填到端口就行**，形如 `https://1.2.3.4:8888`；面板开了「安全入口」才要把入口码一起填上（`https://1.2.3.4:8888/<入口码>`）。App 只在这段地址后面拼模块名（`/system`、`/data`、`/crontab`），安全入口没开却拼了个入口码，或者反过来，回的都是 404 网页不是 JSON。
- **签名是两次 MD5**：`request_token = md5(时间戳 + md5(密钥))`，用 `application/x-www-form-urlencoded` 的 POST 发。时间戳窗口只有几分钟，手机和面板时间差太多会被判认证失败——这一条 App 单独报，不会混成「密钥不对」。
- **失败几乎全是 HTTP 200**。成不成只看响应体的 `status`；`msg` 有时是一句话、有时是一串校验错误（用「；」拼起来）。认证和白名单类的拒绝回的是 HTML，所以先看 Content-Type 再决定解不解 JSON。自检失败那页摊三段：是什么、那句话、下一步做什么——只有面板真写过的那句才标「面板原话」，连不上之类是我们的判断。
- **同一份数据有好几种形状**：`GetNetWork` 是没有信封的裸对象，`GetCrontab` 是裸数组，`getData` 裹成 `{"data":{"rows":[…],"records":N}}`，字段名还按版本变（`name` / `sName`、`cycle` / `where1`）。解析层的规矩是「认得就转成数，认不出原样带出来，两者都不成就说『面板没给』」——不把没给的东西写成 0，读不出的键排在「面板还给了这些」下面，总条数没给就不写「共 N 条」。
- **13.1.0 实测到的几件反直觉的事**（单测里的 fixture 就是这几条原文）：`GetSystemTotal` 全是摊平的键（`cpuRealUsed` / `memTotal` 单位 MB / `time` 是一句「41天」），**它根本不给负载**，负载、内存百分比、磁盘、站点计数只在 `GetNetWork` 里，所以看板把这两个合着读，`GetNetWork` 单独挂掉也不该让整页没数据；`GetDiskInfo` 给的是**按下标排的位置数组**（`size[总, 用, 剩, 率]`、`byte_size[总, 用, 剩]`），不是带键名的对象；`getData` 的 `records` 常常不在，总数写在旁边那段分页 HTML 的「共 N 条」里，只能把它抠出来。
- **数据库列表的回包里带明文密码**（`password` 键原样往外吐）。这一层直接按键名黑名单丢掉，不上屏、不进日志，所以上屏的只有库名、备注、时间、备份份数那几项；计划任务里几十行的 `sBody` 脚本同样不进列表格，要看得点「看日志」。
- **这把密钥等同服务器 root**，面板没有只读作用域。所以它和 NoLine 密钥一样只存 Keystore 密文，界面只出掩码，改地址时留空表示沿用原来那把。停止 / 重启服务、重载面板这三样要亲手打一遍关键词才放行，不打或打错，「执行」按不动。
- **信任自签证书是有代价的**：面板基本都是自签证书，不开这一条 TLS 握手直接失败；开了那一段 App 就不再核对「对面到底是不是你那台面板」，只建议在自己能控制的网络里用。

### 通用调用台：文档里的每一条都摆出来

- **是数据驱动的，不是 329 个手写页面**：整份目录是 `app/src/main/assets/bt_catalog.json`，从 `docs.bt.cn/api` 的 `llms.txt` 和按 action 拆开的 markdown 页抓成的一条条 `{模块、action、路径、动词、参数表}`，界面只认这份数据。面板加了接口只要换那份 json，不用发版；界面上那句「随包打的那份接口目录没读出来」只在 json 真损坏时出现。
- **危险分级照文档自己的归类分三档**：`只读`点了就跑，`会改`弹窗确认一次，`会删`要亲手打一遍「删除」两个字。必填项没填齐哪儿都不去——拦在弹窗之前，不是点了「执行」才回过头说缺参数。
- **两种请求形状都支持**：action 风格的走 `POST /<模块>` 并在表单体里带 `action=…`；路径风格的（Docker、Java 项目、反向代理那批）按文档给的动词走 `/mod/…`。参数表没写全的接口可以「加一行参数」自己补，但 `request_time` / `request_token` / `action` 这三个键锁死，手打也覆盖不掉——签名被顶掉就是「认证失败」，而连续 20 次签名失败面板会锁 API 一小时。
- **回包先脱敏再上屏**：按键名（`password`、`private_key`、`token`、`secret` 这些，含 `_password` / `_key` / `_token` 一类后缀）整块涂成 `***`，所以摆成表格还是给原文都不漏；数组对象摆前 60 行 × 前 5 列，其余字段在下面的整包里，原文截到 4 万字符并写明截断了。像 `keyword` 这种正经字段不会被误伤。

读的那一半已经拿 13.1.0 的正式面板实测过：看板、四张表、任务日志在真机上逐屏走通，上面那些形状就是照着实测回包写的。写的那一半分两种：网站、数据库、FTP、计划任务这几页的建 / 改 / 启停 / 删除，是在正式面板上用一批 `aa-test-*` 命名的临时对象（自建自删，跑完就清干净）验的，面板上原来那些站点、库、账户、任务一律只读；服务启停、重载面板这类只碰得到整台机器的动作，还是只在本地自签 HTTPS 假面板上验过。真面板接上后哪块读不出来，那页会把面板的原文摊在那里。

## 已知限制

- **全站搜索只有 10 条**：Typecho 的搜索 RSS 硬上限 10 条且不翻页，XML-RPC 里也没有搜索方法（`wp.getPosts` 未实现）。App 用「本机已加载的笔记」补一段，但两边都没搜到的老文章仍然搜不出来。
- **登录密码**：勾了「记住登录状态」时以明文存在 DataStore 里（XML-RPC 每次请求都要带原文密码）。NoLine 密钥则走 Keystore 加密。想统一的话，把密码也搬进 `SecretStore` 就行。
- **明文站点**：`network_security_config` 全局禁了 cleartext，http 站点用不了，需要自己放开。
- **多作者场景没做过**：分类判定、日记时间线这些逻辑是按「站主一个人写」设计的，换个多人博客可能要做适配。
- **点赞 / 收藏只在本机**：Typecho 没有对应的原生接口，所以是本地状态，换设备不会同步。
